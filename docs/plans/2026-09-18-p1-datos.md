# P1 · Datos (M1) · Plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: `superpowers:subagent-driven-development` o
> `superpowers:executing-plans`. Casillas (`- [ ]`) para seguimiento.

**Objetivo:** convertir el recorte de Lichess en los seis datasets `chorcat/rukh-*` con manifiesto,
el tokenizador UCI en Python y TypeScript con fixture de paridad publicado como
`chorcat/rukh-tokenizer`, dataloaders con empaquetado por bloques, y la lección M1 con el
`TokenizerPlayground` en el curso.

**Arquitectura:** pipeline `rukh data fetch → uci → tokenize → positions → evals → puzzles → pairs
→ elite → elo-bins → publish`, cada paso un módulo en `src/rukh/data/` con config pydantic
(`extra="forbid"`), salida parquet/npy en `data/` (gitignored) y una entrada en el manifiesto. El
tokenizador de vocabulario fijo es una enumeración determinista (no depende de datos) implementada
dos veces (Python y TS) y verificada por una fixture generada desde Python.

**Stack:** DuckDB `hf://` (httpfs), python-chess, `tokenizers` (BPE), numpy memmap, torch
`Dataset`/`DataLoader`, `huggingface_hub` (publicación), Jinja2 (cards); Preact + Vitest en las webs.

**Spec:** `docs/spec/01-datos.md`, `docs/spec/03-curriculo.md` (M1), `docs/spec/04-web-curso.md`
(TokenizerPlayground), `GOAL.md` (P1). Plan previo: `2026-09-18-p0-scaffold.md`.

- `standard-chess-games` 2025-01: 72 ficheros `train-000NN-of-00072.parquet`, cronológicos (el 0
  es el 1 de enero, 1 394 617 partidas). Los filtros de `docs/01` dejan el **18 %** (251 618 de
  1 394 617) → ≈ 18 M partidas/mes, muy por encima de los 3-6 M por dos meses del spec. Un escaneo
  completo de un fichero tarda ~40 s; una consulta con `LIMIT` termina en 2-3 s (streaming).
  **Decisión:** `limit: 3_000_000` por mes (≈ 12 ficheros, primeros ~5 días del mes) → 6 M
  partidas. Se registra en el manifiesto como recorte temporal (D-017).
- `Event` es `Rated Blitz game`, `Rated Bullet game`, `Rated Rapid game`, `Rated Classical game`,
  `Rated UltraBullet game` o `Rated <X> tournament <url>`. No hay variantes en este dataset; el
  filtro `NOT ILIKE '%variant%'` es inocuo y se mantiene.
- `chess-position-evaluations`: 20 ficheros `data_0000..0019.parquet` (≈ 42 GB); columnas
  `fen (4 campos), line (PV UCI), depth, knodes, cp, mate`; **varias filas por FEN** (≈ 7 de media:
  una por línea principal, ordenadas de mejor a peor para el bando que mueve; `cp` desde el punto
  de vista de las blancas). Sirve para valor (mejor línea) y para pares DPO (primera jugada de la
  mejor línea frente a la de una línea peor con Δcp ≥ 100) sin ejecutar Stockfish.
- `chess-puzzles`: columnas confirmadas (`PuzzleId, GameId, FEN, Moves, Rating, RatingDeviation,
  Popularity, NbPlays, Themes, OpeningTags`).
- Elite DB: `https://database.nikonoel.fr/lichess_elite_2025-01.zip` (82,7 MB, `application/zip`).

## Tarea 3: tokenizador UCI de vocabulario fijo (Python) + fixture

**Enumeración (idéntica en TS, T7):**
1. Casillas en orden *file-major*: `a1, a2, …, a8, b1, …, h8` (índice `f*8 + r`).
2. Jugadas: para cada `from` en ese orden, para cada `to` en ese orden, `from != to`, incluir si
   `to` es alcanzable desde `from` por una dama (misma fila, columna o diagonal) o por un caballo.
   Son **1 792** cadenas `fromto`.
3. Promociones: para cada `from` en rango 7 (blancas) y luego rango 2 (negras), en orden de casilla;
   para cada `to` en rango 8 (resp. 1) con `|Δfile| ≤ 1`, en orden de casilla; para cada pieza en
   `q, r, b, n`: `fromto+piece`. Son **176**. Total de jugadas: **1 968**.
4. Especiales antes que las jugadas, en este orden: `<pad>`=0, `<bos>`=1, `<eos>`=2, `<mask>`=3,
   `<unk>`=4, `<1-0>`=5, `<0-1>`=6, `<1/2>`=7, luego `<w0600>`…`<w3200>` (27 tramos de 100,
   ids 8-34) y `<b0600>`…`<b3200>` (ids 35-61). Jugadas desde el id **62**. Tamaño total **2 030**.
5. Elo → tramo: `clamp(elo, 600, 3299) // 100 * 100`, formateado con 4 dígitos.

```python
class UciTokenizer:
    vocab: dict[str, int]; ids: list[str]
    def encode_game(self, uci: str, white_elo: int, black_elo: int, result: str, max_len: int = 200) -> list[int]
        # [<bos>, <wXXXX>, <bXXXX>, moves..., <result>, <eos>] truncado a max_len (siempre termina en <eos> si cabe)
    def decode(self, ids: list[int]) -> list[str]
    def export(self, path: Path) -> None   # vocab.json: {"version":1,"specials":[...],"elo_bins":{...},"tokens":[...]}
```

## Tarea 6: posiciones, evaluaciones, puzles, pares, Elite y tramos de Elo

- `positions.py`: de `data/uci` toma hasta `n_games` (config, 300 000) partidas del mes 01,
  recorre las posiciones con python-chess y escribe `data/positions/positions.parquet`: `fen4`
  (piezas, turno, enroques, al paso), `game_id`, `ply`, `last_move`, `result`, `phase`
  (`opening` ≤ 10 plies, `middlegame` > 10 plies y ≥ 14 piezas, `endgame`), deduplicado por `fen4`
  con conteo `n_seen`. Tope `max_positions` 5 000 000.
- `evals.py`: `rukh data evals [--files 0-19]`: para cada `data_00NN.parquet` remoto, DuckDB
  `SELECT e.* FROM read_parquet(remote) e SEMI JOIN positions p ON e.fen = p.fen4` → escribe
  `data/evals/part-NN.parquet` (resumible: salta partes existentes), luego consolida
  `positions-eval.parquet` con la mejor línea por FEN (`min` cp para negras / `max` para blancas
  entre líneas de máxima profundidad; `mate` con prioridad) y `pvs` (lista de `{move, cp, mate}`
  de todas las líneas). Registra cobertura en el manifiesto.
- `puzzles.py`: descarga `chess-puzzles` (DuckDB `hf://`), filtra `RatingDeviation ≤ 100` y
  `NbPlays ≥ 100`, tramos `1000-1500 / 1500-2000 / 2000+`, split por `PuzzleId` con semilla 42:
  `test` = 2 000 por tramo, `train` = hasta 50 000 por tramo. Columnas `puzzle_id, fen, moves
  (UCI), rating, themes, band, split`.
- `pairs.py`: desde `positions-eval.parquet`: para cada FEN con ≥ 2 líneas, `chosen` = primera
  jugada de la mejor línea, `rejected` = primera jugada de una línea con Δcp ≥ 100 (desde la
  perspectiva del que mueve; mate cuenta como ±10 000); una pareja por FEN; equilibrado por `phase`
  (mínimo por fase = el menor de las tres, tope 200 000 por fase). Columnas `fen, chosen,
  rejected, cp_chosen, cp_rejected, phase`. Verificación con python-chess de que ambas jugadas son
  legales.
- `elite.py`: descarga `lichess_elite_2025-01.zip` y `2025-02` a `data/elite/`, extrae PGN,
  convierte con `uci.py` (mismo esquema de columnas) → `data/elite/games.parquet`. Manifiesto con
  la URL y sha256 del zip.
- `elo_bins.py`: desde `data/uci` (ambos meses), tramo = `avg(white_elo, black_elo) // 100 * 100`;
  hasta `n_per_bin` (50 000) partidas por tramo con semilla → `data/elo-bins/games.parquet`
  (+ columna `bin`).
