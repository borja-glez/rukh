# P2 · Decoder (M2) · Plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: `superpowers:subagent-driven-development` o
> `superpowers:executing-plans`. Casillas (`- [ ]`) para seguimiento.

**Objetivo:** un decoder GPT escrito a mano (`MoveDecoder`) entrenado desde cero sobre el recorte de
P1, con harness de evaluación (legalidad, exactitud, puzles, Elo contra Stockfish con intervalo de
confianza), exportación a ONNX fp16/int8 con paridad, publicación de `chorcat/rukh-tiny` y
`chorcat/rukh-small`, demo jugable contra el modelo real en WebGPU y lección M2 con `AttentionMap` y
`TrainingReplay`.

**Arquitectura:** `src/rukh/models/decoder.py` (modelo puro, sin dependencias del pipeline),
`src/rukh/train/` (bucle propio con AdamW + coseno, bf16, `torch.compile`, checkpoints y MLflow),
`src/rukh/eval/` (harness con caché SQLite), `src/rukh/export/` (ONNX + cuantización + paridad).
La demo carga los pesos del Hub en un worker de `onnxruntime-web`; el hilo principal enmascara con
`chess.js` y muestrea.

**Stack:** torch 2.11+cu128 (SDPA, sin flash-attn), numpy memmap de P1, MLflow, python-chess +
Stockfish 19, onnx/onnxruntime 1.30, `onnxruntime-web` 1.30 en la demo.

**Spec:** `docs/spec/02-modelos-y-entrenamiento.md` (componentes 1, 5 y 6), `docs/spec/03-curriculo.md`
(M2), `docs/spec/05-web-demo.md` (fase 1), `GOAL.md` (P2). Plan previo: `2026-09-18-p1-datos.md`.

## Tarea 1: `MoveDecoder` con tests

**Ficheros:** `src/rukh/models/{__init__,decoder.py,config.py}`, `tests/unit/test_decoder.py`.

```python
class DecoderConfig(BaseConfig):
    vocab_size: int = 2030; n_layer: int = 12; n_head: int = 8; d_model: int = 512
    d_ff: int | None = None          # None → 4*d_model
    block: int = 200; dropout: float = 0.0
    pos: Literal["learned", "rope"] = "learned"
    tie_embeddings: bool = True
PRESETS = {"tiny": DecoderConfig(n_layer=6, n_head=4, d_model=256),
           "small": DecoderConfig(),
           "medium": DecoderConfig(n_layer=16, n_head=12, d_model=768)}
class MoveDecoder(nn.Module):
    def forward(self, idx: Tensor, targets: Tensor | None = None) -> tuple[Tensor, Tensor | None]
    @torch.no_grad()
    def next_logits(self, idx: Tensor) -> Tensor        # logits del último paso
    def num_params(self, non_embedding: bool = True) -> int
```
Bloques pre-norm: `x = x + attn(ln1(x)); x = x + mlp(ln2(x))`, atención causal con
`F.scaled_dot_product_attention(..., is_causal=True)`, MLP GELU, `LayerNorm` final, `lm_head` atado
al embedding. Init: normal(0, 0.02), escalado `0.02/sqrt(2*n_layer)` en las proyecciones de salida.

- [ ] Tests (CPU, `tiny` de juguete `n_layer=2, d_model=32`): formas `(B, T, V)`; causalidad (cambiar
      `idx[:, t+1:]` no altera `logits[:, :t+1]`); `targets` produce pérdida escalar con
      `ignore_index=0`; `pos="rope"` misma forma y causalidad; `num_params` de `small` entre 38M y
      45M; determinismo con semilla; `next_logits` coincide con `forward(...)[0][:, -1]`.
- [ ] Commit `feat(models): add the MoveDecoder GPT with causal attention`.

## Tarea 2: bucle de entrenamiento con MLflow

**Ficheros:** `src/rukh/train/{__init__,loop.py,schedule.py,checkpoint.py}`,
`configs/train/{tiny,small}.yaml`, `tests/unit/test_{schedule,checkpoint,loop}.py`.

```python
class TrainConfig(BaseConfig):
    preset: Literal["tiny","small","medium"] = "small"; model: DecoderConfig | None = None
    tokens_dir: str = "data/tokens/uci"; block: int = 200
    batch_size: int = 64; grad_accum: int = 4          # 256 secuencias efectivas
    lr: float = 6e-4; min_lr_ratio: float = 0.1; warmup: int = 1000; max_steps: int = 20000
    weight_decay: float = 0.1; betas: tuple[float,float] = (0.9, 0.95); grad_clip: float = 1.0
    precision: Literal["bf16","fp32"] = "bf16"; compile: bool = True
    eval_every: int = 500; eval_batches: int = 50; ckpt_every: int = 1000
    out_dir: str = "checkpoints"; seed: int = 42; run_name: str | None = None
def lr_at(step: int, cfg: TrainConfig) -> float          # warmup lineal + coseno hasta min_lr
def train(cfg: TrainConfig) -> Path                       # devuelve el checkpoint final
```
Cada `eval_every` pasos: pérdida de validación sobre `data/tokens/uci/val` y `top1` de siguiente
token; se registra en MLflow (`start_run` de P0) junto a `tokens/s`, `lr` y `grad_norm`. Checkpoint
`{step, model_state, opt_state, cfg, vocab_hash, data_manifest_sha, git_sha}` en
`checkpoints/<run>/step-<n>.pt` más `best.pt` por pérdida de validación. Reanudación con `--resume`.

- [ ] Tests CPU: `lr_at` sube linealmente hasta `warmup`, llega a `lr`, decae a `min_lr_ratio*lr` en
      `max_steps` y no baja de ahí; guardar y recargar un checkpoint reproduce los pesos y el paso;
      `train` con `max_steps=3` sobre un memmap de juguete baja la pérdida y escribe el checkpoint
      (marcado `unit`, CPU, sin compile).
- [ ] Commit `feat(train): add the training loop with cosine schedule and MLflow logging`.

## Tarea 3: muestreo con máscara de legalidad

**Ficheros:** `src/rukh/infer/{__init__,sampler.py,game.py}`, `tests/unit/test_sampler.py`.

```python
class SampleConfig(BaseConfig):
    temperature: float = 0.6; top_k: int | None = 20; mask_illegal: bool = True; seed: int | None = None
def legal_token_ids(board: chess.Board, tok: UciTokenizer) -> list[int]
def pick_move(model, tok, board, history_ids, cfg) -> tuple[chess.Move | None, dict]
    # dict: {'legal': bool, 'raw_token': str, 'top5': [(uci, prob)], 'masked': bool}
def play_game(model, tok, opponent, cfg) -> GameResult
```
Sin máscara, `raw_token` puede ser ilegal: se devuelve `legal=False` (así se mide la legalidad real).
Con máscara, los logits de tokens no legales se ponen a `-inf` antes del softmax.

- [ ] Tests: `legal_token_ids` en la posición inicial devuelve 20 ids y todos decodifican a jugadas
      legales; con máscara, 1 000 muestreos de un modelo aleatorio nunca dan jugada ilegal;
      `temperature→0` equivale a argmax; promoción forzada produce un token de promoción.
- [ ] Commit `feat(infer): add masked sampling and self-play helpers`.

## Tarea 4: harness de evaluación v1

**Ficheros:** `src/rukh/eval/{__init__,suite.py,legality.py,accuracy.py,puzzles.py,elo.py,cache.py,report.py}`,
`configs/eval/full.yaml`, `tests/unit/test_{legality,accuracy,puzzles,elo,cache}.py`.

- `legality`: 10 000 posiciones de validación (prefijos de partidas del mes 02), % de jugadas legales
  sin máscara.
- `accuracy`: top-1 y top-3 contra la jugada humana, global y por tramo de Elo.
- `puzzles`: `data/puzzles` de P1, 2 000 por tramo; resuelto = acierta **toda** la secuencia.
- `elo`: 100 partidas por nivel contra Stockfish (`UCI_Elo` 1320/1500/1800/2000, `Skill Level` 0-3
  por debajo), ambos colores, con máscara; Elo por regresión logística (`scipy` no: implementación
  propia por Newton con 2 parámetros) e IC del 95 % por bootstrap sobre los resultados.
- `cache`: SQLite con clave `(model_sha, suite, item)` para no repetir partidas ni puzles.
- `report`: Markdown + JSON en `artifacts/eval/<model>/`, y `artifacts/web/results.json` con la fila
  de la tabla única (columnas de `docs/spec/02` §5).
- CLI: `rukh eval --model <ckpt|hub-id> --suite full|quick [--no-cache]`.

- [ ] Tests con un modelo de juguete y Stockfish marcado `engine`: la regresión logística recupera un
      Elo conocido con datos sintéticos; el IC contiene el valor verdadero en ≥ 90 de 100 simulaciones;
      la caché evita la segunda ejecución; `puzzles` cuenta bien secuencias parciales.
- [ ] Commit `feat(eval): add the v1 evaluation harness with cached Elo estimation`.
